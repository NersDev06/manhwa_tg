## Устройство

Индекс перечисляет расширения; сами главы находятся на сайтах. Расширения написаны на Kotlin для Android/Mihon, используют Android API, KeiSource, OkHttp, Jsoup и общие модули lib-multisrc. APK нельзя просто импортировать в Python. Для небольшого серверного приложения рационально реализовать отдельный адаптер нужного сайта по изученной логике. Универсальный исполнитель расширений — отдельный, более сложный проект.

В src/ru найден 31 каталог модулей; число модулей не равно числу сайтов или гарантированно работающих источников.

## Проверка доступности

Обычный curl с TLS-проверкой и переходами по редиректам:
- https://mangabuff.ru/manga — HTTP 200.
- https://mangalib.me — HTTP 200.
- https://a.zazaza.me — HTTP 402. Причина по одному коду не установлена.

Результаты: research/source-checks.json. Это проверка HTTP-доступности, а не работоспособности чтения глав. Каталог, конкретные главы, полнота изображений, PDF и Telegram ещё не проверялись. Python urllib в текущем окружении столкнулся с локальной ошибкой доверия сертификатам; curl выполнил запросы без отключения TLS-проверки.

## Рекомендуемый план реализации

1. Проверить каталог MangaBuff и подобрать одну доступную манхву для теста метаданных.
2. Реализовать адаптер: поиск, сведения о произведении, все главы с догрузкой, упорядоченный список изображений.
3. Добавить SQLite: произведение, источник, стабильный ID главы, том/номер как строки, ветка перевода, целевой канал, состояние публикации и ID сообщения Telegram.
4. Добавить загрузку и PDF: сохранять порядок страниц, поддержать длинные вертикальные изображения, не публиковать неполные главы.
5. В тестовом канале проверить отправку, ограничения размера, повторный запуск и восстановление очереди.
6. При неоднозначном исходе отправки в Telegram отмечать состояние для проверки: простой повтор запроса может создать дубль. Абсолютную гарантию отсутствия дублей заранее не обещать.
7. Подключить планировщик, ограничение запросов, задержку повторов, журнал и уведомления. Ошибку или пустой ответ не считать отсутствием новых глав.
8. Затем подключить остальные манхвы и каналы через настройки, добавляя новые сайты отдельными адаптерами.

Исходники используются с соблюдением Apache-2.0; при переносе кода сохранить необходимые уведомления и лицензию. Лицензия кода не предоставляет прав на произведения.

## Перед разработкой

Нужно определить первые тайтлы, стартовую главу/архив и ветку перевода при наличии нескольких. Токен бота позднее сохраняется локально в игнорируемом файле окружения. Сейчас разработка приложения и публикации не выполнялись; существующие пользовательские папки не читались.

## Уточнение: MangaShi и Heroku

MangaShi уже есть в Keiyoushi: src/ru/mangashi, имя Manga-shi, versionCode 52, baseUrl https://manga-shi.org. Поэтому искать другой репозиторий для этого источника сейчас не требуется.
Код использует HTML: каталог #manga-grid, главы #chapters-list, догрузку через hx-get и пагинацию, страницы img.reader-image с data-src/src. Задан rateLimit(2).
Проверен живой каталог https://manga-shi.org/catalog/?sort=updated: HTTP 200, заголовок «Каталог — Mangashi», 21 уникальная ссылка, содержащая /manga/. HTML сохранён в research/mangashi-catalog.html. Конкретные главы и изображения пока не проверены. Приоритет первого адаптера меняется с MangaBuff на MangaShi по пожеланию пользователя.

Heroku: студенческая программа по официальной справке даёт $13/месяц на 24 месяца (срок конкретного аккаунта нужно смотреть отдельно). Предлагаемый бюджет: один Basic worker $7 + Mini Postgres $5 = $12/месяц. Один процесс обслуживает все каналы и последовательно обрабатывает главы; отдельные Redis, web dyno и хранилище архива в первой версии не нужны. Сумма предполагает отсутствие других платных ресурсов аккаунта. Скорость и память должны быть проверены реальной главой.
Для Heroku заменить план SQLite на Postgres: локальный диск временный, файлы удаляются после перезапуска. PDF и изображения — только временные файлы обработки, состояние очереди и публикаций — в Postgres. Публикация старого архива постепенно, без загрузки всех глав в память.
Источники: https://help.heroku.com/Z3RHNRHD/how-does-the-heroku-for-github-students-program-work ; https://www.heroku.com/pricing/ ; https://devcenter.heroku.com/articles/dynos#ephemeral-filesystem
