# Отчёт: MangaShi → Telegram

18 октября 2026. Проект находится только в `manhwa-telegram`; существующие пользовательские папки не читались.

## Уже сделано

- Python-приложение: источник MangaShi, поиск и полная пагинация глав, дробные главы и экстра-ссылки без тома, загрузка изображений и сборка PDF.
- Одно исходное изображение становится одной длинной PDF-страницей: текст и рисунки не разрезаются. PDF автоматически делится на файлы менее 45 МБ.
- Последовательная очередь MongoDB, глобальная аренда worker с heartbeat, повторы временных ошибок, блокировка неоднозначных отправок, восстановление после остановки.
- Лимит 10 разных глав в сутки для КАЖДОГО канала по Asia/Bishkek; между заданиями пауза 60 секунд. Повторы одной главы в тот же день не съедают новое место.
- Команды настройки, паузы, состояния и ручного разрешения неизвестного результата отправки.
- Первые успешные отправки сохранены в config/bootstrap-receipts.json и будут учтены при заполнении очереди.
- Токен сохранён в локальном .env с правами 600 и в Heroku Config Vars; в Git и исходном коде его нет.

## Heroku

Приложение: https://dashboard.heroku.com/apps/manhwa-publisher-20261018
Регион Europe, стек Heroku-24, Python 3.13, Basic worker. Код успешно собран и развёрнут. Дополнительных платных баз/Redis нет.

Постоянный worker включён: **1 экземпляр Basic**. MongoDB подключена из Heroku. Архив из 267 записей и первые две проверочные отправки занесены в базу; повторно они не публикуются.

Две проверки реальных глав выполнены непосредственно в одноразовых Basic dyno:

| Глава | Результат | Пик основного процесса | Пик конвертера |
|---|---|---:|---:|
| Рыцарь, пролог | PDF собран и повторно открыт, 7 страниц | 69.2 MiB | 123.1 MiB |
| Регрессор, глава 1 | PDF собран и повторно открыт, 20 страниц | 87.6 MiB | 104.8 MiB |

Одновременно работает один конвертер. Сумма измеренных пиков в обоих примерах около 192 MiB; это оценка верхней границы по двум процессам, а не измерение суммарного RSS в одну и ту же миллисекунду. Будущие главы иных размеров могут потребовать дополнительной проверки. Установлены пределы размера входного изображения.

После включения одного Basic worker ожидаемая стоимость вычислений — до $7/месяц по текущему тарифу. Разовые проверочные dyno расходуют небольшую долю кредита отдельно. M0 бесплатный; дополнительные платные сервисы не подключены.

## MongoDB

Создан отдельный проект Manhwa Telegram, ID 6ad459ab769b128a91985d10, бесплатный кластер manhwa в AWS Ireland, лимит хранения 512 МБ.

В новом проекте после разрешения пользователя применён сетевой доступ 0.0.0.0/0 для динамических исходящих IP Heroku. Это открывает сетевую достижимость со всех IPv4, но не отменяет обязательную аутентификацию и TLS. Старые проекты и пользователи не менялись.

Пользователь NersDev06 создан владельцем, роль readWrite только для manhwa_telegram. Строка подключения сохранена в локальном .env и Heroku Config Vars. Для TLS явно используется доверенный набор certifi; проверка сертификатов включена. По просьбе владельца данные доступа сохранены в Telegram «Избранное». Пароль и URI в отчёт и Git не включены.

## Рабочее состояние

- Источник → PDF проверен на Heroku для обеих выбранных манхв.
- Очередь и индексы созданы в настоящем Atlas; источник и Telegram связаны через один постоянный worker.
- Первые ручные публикации импортированы с Telegram message ID и file ID.
- На момент замера данные занимают 104 984 байта, индексы 212 992 байта (в сумме около 0.30 MiB из доступных 512 МБ).
- Лимит по 10 глав в сутки на каждый канал; первые проверочные главы учитываются в сегодняшнем лимите.

## Проверки и ограничения

- 14 автоматических тестов прошли: пагинация, дробные номера, отсутствие повторов, блокировка после ошибки, восстановление неизвестной отправки, одна аренда worker, суточные лимиты на канал и сохранность изображения.
- Автоматические тесты очереди использовали mongomock. Дополнительно выполнена настройка и проверка рабочего состояния в настоящем Atlas.
- Реальные PDF отрисованы для визуального просмотра; обе публикации подтверждены API Telegram и просмотром канала.
- При неизвестном результате отправки автоматический повтор запрещён. При изменении оригинальной главы между попытками многочастной отправки может потребоваться ручная проверка.
- Автопочинка изменившейся разметки сайта не обещается; об ошибках сообщают status/логи. Личные уведомления доступны после задания ADMIN_CHAT_ID.
- Круглосуточная публикация работает на Heroku; локальный компьютер для неё не нужен.

## Завершённая проверка запуска

Подключение Atlas проверено локально и непосредственно из Heroku. Постоянный Basic worker запущен. Автоматически опубликованы глава 1 «Рыцаря» и глава 2 «Регрессора». Затем выполнен контролируемый перезапуск worker между заданиями: предыдущие 4 записи отправки и их Telegram receipts сохранились, появился новый владелец аренды, после перезапуска автоматически отправлена следующая глава. На момент проверки неизвестных результатов отправки — 0; ID сообщений не дублируются. Подробности без секретов: research/restart-verification.json и research/live-verification.json.

Ожидать действий владельца для запуска больше не требуется. Процесс работает на Heroku независимо от локального компьютера. Платный Mini Postgres не используется, студенческие кредиты MongoDB не нужны для бесплатного M0.
