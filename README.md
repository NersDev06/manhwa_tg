# Manhwa Telegram

Текущий режим: один облачный Heroku Basic, пауза 10 секунд. Локальный воркер выключен.
[Отчёт о переносе и проверке памяти](HEROKU-2026-10-19.md).

Один последовательный worker публикует главы в Telegram-каналы через проверенную цепочку MangaShi → WaManga → MangaBuff → ReManga.
Подробности актуального обновления: [SOURCES-2026-10-19.md](SOURCES-2026-10-19.md).
Читатели взаимодействуют только с каналами; бот служит техническим издателем.

## Локальная установка

Требуется Python 3.13+.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполнить `MONGODB_URI` и `TELEGRAM_BOT_TOKEN` в `.env`. Не добавлять его в Git.
Если файл уже существует, не перезаписывать. MongoDB: отдельный M0 и пользователь
с `readWrite` только для базы `manhwa_telegram`. Использовать TLS и ограниченный
сетевой доступ. Не включать автоматическую выдачу административных прав.

## Проверка источника и PDF без базы

```sh
.venv/bin/python -m manhwa search 'Начало после конца'
.venv/bin/python -m manhwa chapters 'https://manga-shi.org/manga/the-beginning-after-the-end/'
.venv/bin/python -m manhwa preview 'https://manga-shi.org/manga/the-beginning-after-the-end/tom-1/glava-1/'
```

`preview` создаёт PDF локально и ничего не отправляет. Изображения преобразуются
по одному в отдельных короткоживущих процессах; одновременно работает только один
конвертер. Каждое исходное изображение становится отдельной длинной страницей
PDF в исходных пропорциях: рисунки и реплики не разрезаются. Для чтения удобно
использовать прокрутку по ширине страницы. GIF обрабатывается как первый кадр.
Изображение более 32 млн пикселей или файл более 30 МБ вызывает ошибку,
а не публикацию неполной главы. Обычная глава отправляется одним PDF. Только большие главы делятся с безопасным потолком 49 МБ на файл (Bot API допускает до 50 МБ).

## Подключение канала

Добавить бота администратором с правом публикации, затем:

```sh
.venv/bin/python -m manhwa check-channel '@channel_name'
.venv/bin/python -m manhwa init-db
.venv/bin/python -m manhwa add --url 'https://manga-shi.org/manga/title/' --channel '@channel_name' --mode new
.venv/bin/python -m manhwa worker
```

В режиме `new` первый успешный опрос фиксирует существующие главы без публикации;
публикуются только появившиеся при следующих опросах. Чтобы начать с определённой
главы, использовать `--mode archive --start 1`. Номер включительный и применяется
ко всем томам. Архив публикуется последовательно, поэтому не включать его в
публичном канале до проверки тестового канала.

Пауза и состояние:

```sh
.venv/bin/python -m manhwa status
.venv/bin/python -m manhwa pause SUBSCRIPTION_ID
.venv/bin/python -m manhwa resume SUBSCRIPTION_ID
```

## Очередь и восстановление

MongoDB хранит метаданные, очередь, результаты частей PDF и Telegram message/file ID.
Уникальные индексы по URL и `(subscription, volume, number)` защищают от повторного добавления главы при смене источника. Старые неизвестные главы ниже уже опубликованной позиции автоматически не допубликуются.
Глобальная аренда блокирует второй worker и продлевается отдельным heartbeat.
После остановки прерванная загрузка повторяется. Отправка с неизвестным исходом
получает состояние `uncertain`: автоматический повтор запрещён. Такая глава
блокирует следующие главы своего произведения. Другие подписки продолжают работу.

Временные ошибки повторяются с увеличением задержки, максимум 5 попыток. Явные временные отказы Telegram (408/429) продолжают безопасный повтор после задержки; ошибки источника могут вернуться в очередь после успешного опроса каталога.
После этого глава получает `failed`. Проверить канал и выполнить:

```sh
.venv/bin/python -m manhwa resolve JOB_ID --action retry --checked-channel
.venv/bin/python -m manhwa resolve JOB_ID --action sent --checked-channel
.venv/bin/python -m manhwa resolve JOB_ID --action skip --checked-channel
```

Для многочастной главы `sent` означает, что вручную подтверждены ВСЕ части.
При `retry` подтверждённые части пропускаются. Проверить неоднозначную последнюю
часть вручную перед повтором: Telegram не предоставляет ключ идемпотентности.
При изменении оригинала между попытками состав частей может измениться — в этом
случае требуется ручная проверка и восстановление, автоматической гарантии нет.

`ADMIN_CHAT_ID` необязателен: владелец должен сначала открыть бота и нажать Start.
Без него ошибки доступны через `status` и логи Heroku. Подробные stack traces и
строки подключения не выводятся в логи.

## Heroku

Файлы для деплоя: `Procfile`, `.python-version`, `requirements.txt`, `.slugignore`.
Только один `worker` Basic, без web dyno, Redis и платной базы Heroku.
Задать Config Vars из `.env`, затем задеплоить проект и включить worker.
Локальный диск Heroku временный. Telegram-квитанции хранятся в MongoDB, подготовленные PDF — в локальном spool. При потере spool после частичной отправки автоматическая пересборка запрещена: нужно вручную восстановить исходные части или проверить доставку. Успешно отправленные задания очищаются.

Конкретные команды `heroku git:remote`, `git push` и `heroku ps:scale` выполняются
после выбора созданного приложения и проверки учётной записи CLI.

## Очередь и лимиты

`DAILY_CHAPTER_LIMIT=0` снимает суточный лимит. Положительное значение включает
необязательную квоту на каждый канал по Asia/Bishkek. По умолчанию лимита нет.
Один worker обрабатывает одну главу, ждёт 60 секунд и берёт следующее задание.
Тайтлы обслуживаются по очереди; PDF-части одной главы отправляются вместе.
Ответ 429 сохраняет общую паузу Telegram в MongoDB. Неизвестная доставка требует
проверки: автоматического повторного поста не будет.

В `config/channels.json` восемь публичных каналов. Для настройки с остановленным
воркером: `python -m manhwa configure`. Для оформления:
`PYTHONPATH=. python scripts/configure_presentation.py`. Скрипт проверяет публичный
адрес и права, добавляет метаданные, фото и тихий закреплённый навигатор.
Для оформления бот должен иметь can_change_info и can_edit_messages в канале.
Команда `python -m manhwa setup-channel SUBSCRIPTION_ID` повторяет оформление
без повторной отправки навигатора; ссылка на первую главу обновляется воркером.

## Рекомендации и превью

Во время первичного архива рекламы нет. Когда все доступные главы отправлены,
фиксируется счётчик. После каждых трёх новых глав в конце очереди данного канала
отправляется один пост «Вам также могут понравиться» с URL-кнопками остальных
активных публичных каналов. Многочастная глава считается одной. Состояние хранится
в `outbox`; sending при перезапуске становится uncertain, отправленные промо
восстанавливают счётчик. Для ручного разбора проверить реальный канал и документ
outbox: не переводить uncertain обратно в pending без проверки.

`python -m manhwa test-preview CHAPTER_URL` отправляет целый фрагмент средней
страницы в test. Генератор ищет белые разделители и берёт центральный кадр;
это эвристика, не распознавание комиксных панелей. По просьбе владельца превью
включены перед каждой новой главой во всех каналах; они используют уже скачанную
для PDF среднюю страницу. ID превью сохраняется, при повторе PDF картинка не
отправляется снова. Неизвестная отправка превью останавливает главу для проверки. Для теста другого канала есть явный аргумент `--channel`.

## Username и аккаунт владельца

Bot API не создаёт каналы, не назначает username и не включает платные реакции.
Шесть каналов созданы через интерфейс владельца. `seo.usernames` генерирует
кандидаты; существующие публичные ссылки сохраняются.

Дополнительный `owner_username.py` реально использует channels.checkUsername и
channels.updateUsername, пробует следующие свободные кандидаты и сохраняет
FloodWait в owner_tasks с общей паузой аккаунта. Для его использования нужна уже
авторизованная пользовательская Telethon-сессия и собственные Telegram API ID/hash:
установить requirements-owner.txt, задать локально TELEGRAM_OWNER_SESSION,
TELEGRAM_API_ID, TELEGRAM_API_HASH, затем `python -m manhwa.owner_username SUB_ID`.
Модуль не пытается входить в аккаунт или получать код. Сейчас он не подключён к
сессии владельца; текущие публичные адреса проверены через интерфейс и Bot API.
Файлы сессий исключены из Git и Heroku. Heroku-воркер использует только бота.

## Рабочее развёртывание

Приложение `manhwa-publisher-20261018`, Europe, один Basic worker и Atlas M0.
Секреты находятся в локальном .env и Config Vars, отсутствуют в Git.
Нельзя запускать локальную и облачную обработку одновременно: аренда MongoDB
защищает от двух воркеров. Для переноса первичной загрузки достаточно остановить
облачный worker и запустить локально тот же `python -m manhwa worker`; прогресс
сохранится в общей MongoDB. Для памяти это не требуется: декодер изображений
запускается отдельно и освобождает память после каждой страницы.

См. PLAN.md, COMPETITION.md и REPORT.md. Ограничение пересылки не является
гарантией защиты от копирования и жалоб. Свой PDF-контейнер не передаёт права
на иллюстрации и перевод.


## Текущий режим: локальный архив

По просьбе владельца облачный worker выключен, архив обрабатывается локально.
Команды: `.venv/bin/python scripts/local_worker.py start`, `status`, `stop`.
Фоновый сервис launchd работает независимо от чата и автоматически загружается
после входа в macOS. Регистрация: `~/Library/LaunchAgents/local.manhwa-telegram.worker.plist`,
логи: `tmp/local-worker/worker.log`. Команда `stop` снимает регистрацию автозапуска.
Секретов в plist нет. Caffeinate предотвращает обычное idle sleep,
но не гарантирует работу при закрытой крышке или выключенном компьютере.
Переключение на Heroku выполнять после остановки локального worker между главами;
общая MongoDB сохраняет очередь, превью и подтверждения PDF.

## Резерв источника и восстановление

`manhwa/fallback.py` использует проверенные страницы WaManga из config/channels.json,
когда MangaShi недоступен. Сопоставление — по точному номеру главы с сохранением
URL/ID/тома очереди, в том числе при возврате основного источника. Неоднозначные
номера не угадываются. В резерве отсутствуют три спецвыпуска: варвар 80.5. Спецвыпуски Петера 104.1/104.2 доступны через MangaBuff. Они сохранены в очереди и не заменяются соседней главой.

При подтверждённом превью повтор отправляет только отсутствующие PDF-части.
`tmp/spool/<job id>/` сохраняет готовый PDF и состав частей между попытками,
удаляется после полной подтверждённой доставки. При неизвестном результате
отправки по-прежнему нужна проверка канала: Bot API не поддерживает ключ
идемпотентности. Таймаут увеличен; ConnectTimeout отличается от неоднозначного
обрыва после начала передачи. Диагностика конвертера сохраняет причину ошибки.
